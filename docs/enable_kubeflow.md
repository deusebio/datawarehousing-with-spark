## Enable Kubeflow

Kubeflow deployment can be enabled using the `enable_kubeflow` configuration variable, e.g.

```bash
# tfvars.json
{
    enable_kubeflow: true
}
```

This will deploy Kubeflow into its own `kubeflow` namespace. Within the namespace, also the [data-kubeflow-integrator charm](https://github.com/canonical/data-kubeflow-integrator) will be deployed
that will allow integration between Spark (and Kafka) with Kubeflow profile namespaces.

The Terraform bundle will take care of creating the relevant relations between the `kafka:kafka-client` and `integration-hub:spark-service-account` endpoints and the kubeflow integration,
as well as the integration between the kubeflow integration and the resource dispatcher that will take care of creating relevant K8s resources (secrets, service accounts, roles, role-bindings
and pod defaults) in the user namespaces.

Once the entire deployment is up and running, make sure that relevant resources (e.g. pod defaults) are created in the user namespaces, e.g.

```bash
$ kubectl get poddefaults -n admin 
NAME                 AGE
access-ml-pipeline   25m
kafka-pod-default    25m
pyspark-notebook     25m
pyspark-pipeline     25m
```

### Enable Hive support on the Notebooks

At the time of writing, Spark <> Kubeflow integration does not yet support an out-of-the-box integration between the notebooks and the Hive tables generated by the Spark streaming process.

To allow this, we need to feed the Hive configuration manually. To do so, first fetch the `hive-site.xml` from the spark-streaming process

```bash
juju ssh --model kafka --container spark  spark-streaming/0 "cat /etc/spark8t/conf/hive-site.xml" > hive-site.xml
```

Then, convert the `xml` files into a Spark property file using the bundled python script:

```bash
python3 bin/parse-hive-conf.py --input hive-site.xml --output spark.conf
```

Once the Spark property file `spark.conf` is generated, its content can be uploaded to the `spark-user` Spark service account used to run the notebooks

```bash
spark-client.service-account-registry add-config --username spark-user --namespace admin --properties-file spark.conf
```

The overall configurations for the Spark jobs triggered by the notebooks can also be verified using

```bash
spark-client.service-account-registry get-config --username spark-user --namespace admin
```


### Running Spark inside the Notebook

1. In the Kubeflow UI, click "Notebooks" and "+ New notebook".

2. In the setup, click "Custom Notebook" and choose custom image for notebook (under Advanced Options), and specify the charmed-spark-jupyterlab image `ghcr.io/canonical/charmed-spark-jupyterlab:3.4-22.04_edge`. 

3. Scroll down to the bottom. In the "Advanced Options", choose the configuration "Configure PySpark for Kubeflow notebooks", and finally click on "Create". This will apply the poddefault that configures this notebook to access Spark.

4. Once the notebook pod comes up and running, connect to the notebook, and access Spark from within it. In the first cell, you can also just type `sc`. The command will possibly take a few seconds to complete, since it will return only once all executors have started and reported back to the driver (which is the notebook itself). You can also confirm that the executors are starting by using a `kubectl get pod -n admin`, and check the status of the executor pods.

5. Once the SparkSession is correctly initialized, you can then start to connect to the Hive for processing the data being written by the Spark Streaming application, e.g.
```python
spark.sql("SHOW DATABASES").show()
```
and then fetch the tables in the database using
```python
spark.sql("SHOW TABLES in default").show()
```
You can process the data in the table by first (lazy) loading the data into a Spark DataFrame
```python
df = spark.sql("SELECT * FROM <database>.<table>")
```
and then using Spark high-level API to compute aggregation, e.g. 
```python
df.groupby("window").count()
```

### Running Spark from pipeline

1. In the Kubeflow UI, click "Notebooks" and "+ New notebook".

2. In the setup, scroll down to the bottom. In the "Advanced Options", choose the configuration "Configure PySpark for Kubeflow pipelines", and finally click on "Create". 

3. Once the notebook pod comes up and running, connect to the notebook. Upload the file `test_spark_pipeline.ipynb` from [this repo](https://github.com/theoctober19th/kubeflow-spark-poc/blob/main/test_spark_pipeline.ipynb) there, and run it to start a Kubeflow pipeline run.

4. In the terminal, verify that new pods containing `system-container-impl` in the name are created. To see the result of the Spark job run from the pipeline, see the pod logs of that pod.
```bash
kubectl logs -n admin spark-test-pipeline-f4zwt-system-container-impl-427000165 | grep "vowels"
```
